active_games_view — what it is and why it exists

active_games_view is a PostgreSQL VIEW (not a table). It is the only thing loadGames() in db.js queries. It combines two tables in one read:

SourceColumns exposed
games gid, slug, title, short_label, category, wheel_slot, status, emoji, current_version_id, updated_at
game_versions gv (LEFT JOIN on current_version_id)definition (JSONB), version_number, schema_version

Filter: WHERE g.status = 'active' — draft, deprecated, and archived games are completely invisible to the app. The 50 batch-2 games start as draft and will not appear on the wheel until an admin sets their status to active and assigns a wheel slot.

Why a view and not a direct table query? The app needs the game's JSONB definition (instructions, scoring, etc.) alongside the game metadata in a single query. Without the view, every page load would need a JOIN — the view encapsulates that JOIN and lets loadGames() stay a simple .select('*').

RLS note: The anon role's SELECT policy on games (WHERE status = 'active') already restricts what the view can return. The view adds no extra security — it only simplifies the query shape.

After graphic_upgrade.sql: The view is rebuilt to also expose g.emoji. The wheel's label renderer reads game.emoji first (from the view), falling back to the GAME_EMOJI_FALLBACK dict in wheel.js if the column is null (offline / pre-migration).

Error & Settings UI (ui.js)

Appended to DOM by IIFE after DOMContentLoaded. Elements: floating gear button (fixed bottom-right), settings panel (above gear, hidden by default), error panel (inside .app-container, bottom of page).

Persistence: localStorage.getItem('moment_show_errors') = '1' | '0'
Error hook: window._onErrorLogged — set by ui.js, called by db.js _logError
Error source: window._momentErrors[] — populated by db.js, read by ui.js
